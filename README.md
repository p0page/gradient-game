# Gradient

Svelte 5、TypeScript、Vite、pnpm 和 Vitest 项目。界面沿用 Color Link 的浅色卡片、橙蓝席位和胶囊按钮。当前页面提供独立的双人联机测试玩法「凑到 15」。

## 本地开发

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm check
pnpm test
pnpm build
pnpm preview
```

开发可使用 localhost。单台电脑测试双人连接时，使用两个独立浏览器或独立浏览器配置文件，因为同一配置文件下的标签页共用本地对局记录。

跨设备时将 `dist/` 放到双方都能访问的静态 HTTPS 地址，两台设备打开同一个 URL。开局后只交换 WebRTC 数据，无需运行 Node 服务或配置 STUN、TURN、信令服务器。生产构建会缓存页面供离线刷新，首次需在线打开并等缓存完成。

## 配对与续局

1. 两台设备连到同一个可互通的 Wi-Fi。A 生成邀请并将配对码交给 B。
2. B 粘贴邀请，生成回应并把回应交给 A。A 粘贴回应以建立连接。
3. 掉线后回到同一浏览器与同一网页地址，由任意一方从「继续对局」生成新邀请。另一方直接粘贴邀请，页面读取该局在本机保存的记录。打开同一场新配对会覆盖当前网页上的连接。

局域网直连要求网络允许设备之间通信。访客网络的设备隔离可能使配对失败。恢复依赖双方各自浏览器保存的记录，隐私模式、清除站点数据或更换地址可能使原记录无法读取。配对码应直接发给对局另一方。

## 接入另一个游戏

`src/lib/multiplayer/index.ts` 是联机模块入口。它不依赖 Svelte 或测试玩法。

- `WebRtcLink` 创建和解析手动配对的配对码，实现 `MatchLink`。未来可以更换配对方式或提供自己的可信传输实现。
- `MatchSession` 接收游戏的 `MatchRules`、`MatchSeat` 和 `JournalStore`。规则提供初始公开状态、当前可操作席位、动作校验和确定性状态更新。每个版本只允许一个席位提交。随机结果和计时结果需要由游戏转换成可验证的动作。
- `createIndexedMatchStore` 等待事务提交后才确认写入。发送方先保存待确认命令，对方持久化后再回复。重连时双方核对已确认版本和摘要，补交中断的动作。冲突会暂停对局。
- 仅将公开信息交给同步层。暗牌和揭示证明由游戏规则处理。对局协议提供一致性校验，无法保证受修改的客户端会执行规则或完成一局。
